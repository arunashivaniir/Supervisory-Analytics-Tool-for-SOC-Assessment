SAT-SA SMALL EXPERT VALIDATION STUDY
==============================================================================

1. OBJECTIVE
------------------------------------------------------------------------------
  Compare human manual review against SAT-SA output for the three
  existing supervisory signal families, and establish whether those
  signals are useful, explainable and aligned with manual review.
  No new analytics were added. The framework observes the existing
  pipeline result and adds no rule, threshold, score or output key.

2. DATASET DESCRIPTION
------------------------------------------------------------------------------
  20 assessment cases drawn from 4 datasets
  that already exist in the repository. No new dataset was created.
    dataset_capability_rich.csv (2 cases)
    dataset_execution_gap_controlled.csv (4 cases)
    dataset_negative_space_controlled.csv (6 cases)
    dataset_operational_pattern_controlled.csv (8 cases)

3. NUMBER OF ASSESSMENT CASES
------------------------------------------------------------------------------
  20

4. MANUAL-REVIEW METHODOLOGY
------------------------------------------------------------------------------
  A reviewer is given each case's assessment scope and the raw
  submitted rows behind it. They record, per signal family, the
  indicators they observed, the records that support them, their
  reasoning, and their confidence.
  The template ships with every human field empty, so no review is
  implied before one happens. Free text is kept separate from
  indicator comparison and is never matched by string equality.

5. SAT-SA METHODOLOGY
------------------------------------------------------------------------------
  The existing pipeline is run over each corpus dataset. The
  reference output is a verbatim slice of the existing per-scope
  payloads under execution_gap_findings, negative_space_findings and
  operational_pattern_findings. No result schema was modified.

6. COMPARISON METHODOLOGY
------------------------------------------------------------------------------
  Comparison is per indicator, per family, per assessment scope.
  Scope is part of a signal's identity, so an indicator reported for
  the right reason against the wrong entity is recorded as a scope
  mismatch rather than as a match.
  Outcomes: MATCH, MATCH_UNSUPPORTED, SCOPE_MISMATCH,
  FALSE_POSITIVE, FALSE_NEGATIVE.

17. LIMITATIONS
------------------------------------------------------------------------------
  - The corpus is small and controlled. It is designed to exercise the comparison machinery across the signal families and the scope isolation rules. It cannot estimate how the signals perform on real operational data.
  - No expert labels exist yet, so no claim about agreement with a human reviewer is supported by this report.
  - Controlled expectations were written by the framework author from the raw source rows. They are design intent. They are not independent of the system's authors and must not be read as external validation.
  - execution_gap: no case in this corpus pairs a human-reported indicator with a matching SAT-SA indicator, so precision is not defined for this family.
  - negative_space: no case in this corpus pairs a human-reported indicator with a matching SAT-SA indicator, so precision is not defined for this family.
  - operational_pattern: no case in this corpus pairs a human-reported indicator with a matching SAT-SA indicator, so precision is not defined for this family.
  - Concept collisions were observed, meaning more than one source column feeds a single canonical concept: dataset_capability_rich.csv: INVESTIGATION_EVIDENCE is fed by investigation_notes, root_cause_identified. A finding's evidence value for such a concept is ambiguous unless the columns agree, so those findings need human reading rather than automatic acceptance.
  - Precision and recall are undefined wherever a family has no positive or no negative case in the corpus. Undefined is reported as undefined rather than as zero or one.
  - Explanations are recorded as present or absent. Human and tool reasoning is never compared by string equality, so this report cannot and does not measure whether the wording of an explanation is good.
  - The supervisory-value question is a novelty signal about dashboard visibility, not an accuracy measure, and is not scored numerically.
